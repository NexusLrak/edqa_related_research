# 问题发展史：从"贪心太慢"到"eDQA的机制设计是否合理"

这个文件记录整个项目里"问题→假设→验证→结论/转折"这条链条完整的演化过程，是`RESULTS.md`（只记录
站得住的最终结论）和`EXTENSION_WORK.md`（记录2026-07-27起`protection_gain`/`pg·|g|`那一段探索的
详细推理过程）之上的一层更高视角的总览——目的是让人（包括未来的自己）能看清整条研究线是怎么一步
一步从一个很具体的工程问题（贪心算法太慢），演化成一个越来越根本的理论问题（eDQA的协议设计本身
是否合理）的，而不是只看到某一个阶段的局部结论。

每一轮按"问题→假设→验证→结论/转折"四段式记录。数据来源已标注（README.md的"坑"编号 / RESULTS.md
的Section / EXTENSION_WORK.md的节号），可以回查原始记录核实细节。

---

## 第1轮：贪心太慢，能不能用矩阵秩替代？

**问题**：论文Algorithm 3（贪心搜索）是O(L·C)——每个候选通道都要做一次完整推理评估，MobileNetV2上
排序本身要80+分钟，ResNet-18上100+分钟/seed，ViT上后来发现要~19小时/seed（远端RunPod RTX5090）。
这个成本高到没法作为常规实验流程使用。

**假设**：贪心可以被一个便宜得多的surrogate替代。参考剪枝文献里用矩阵/SVD结构信息判断重要性的做法，
预设可以用矩阵秩（SVD方向）当排序依据。

**验证**：ResNet-18/TinyImageNet，3个calib_seed，eDQA 3-bit全测试集。

**结论/转折**：矩阵秩surrogate本身**不符合预期**（mean=63.31%, std=1.77pp，低于贪心的64.29%，方差
还更大）。但验证过程中试了一个"矩阵秩方向搜索margin太小就fallback到energy"的cascade方案，结果发现
**3个seed里除1层外几乎全部fallback到了纯energy**，而且效果几乎跟纯energy完全一样——这个意外的中间
产物（纯energy: mean=66.51%, std=0.20pp）比贪心和矩阵秩都更好，直接催生了下一轮问题。

**数据来源**：`quant/README.md` 坑#12。

## 第2轮：energy在部分模型上不如贪心，还有更好的表达方式吗？

**问题**：第1轮发现的energy虽然在ResNet-18上大赢，但跨模型验证后发现**不是普适更优**——ResNet-32上
贪心（89.19%）明显赢energy（87.45%），效果依赖模型/架构。

**假设**：energy只测了channel自身的激活幅度，可能遗漏了"下游是否敏感"这一半信息。参考量化误差对
loss的一阶Taylor展开`ΔL≈(∂loss/∂x)·Δx`，`Δx∝幅度/2^N`——如果把梯度也算进去（`saliency=Σ|a|·|g|`），
可能比纯幅度更贴近Algorithm 3自己对"重要"的因果定义。

**验证**：四个模型（ResNet-18/32、MobileNetV2、ViT）全测，5-seed（贪心太贵仍3-seed）。

**结论/转折**：energy和saliency**都有不俗表现**，但优势方向不一致——saliency在ResNet-32(+1.08pp)、
MobileNetV2(+0.27pp)、ViT(+0.64pp)三个模型上稳定优于energy，**只有ResNet-18是例外**（-2.23pp，用
排除法测过ReLU门控/TinyImageNet覆盖/224分辨率/BatchNorm/迁移学习等候选原因，最后落在r=0.55这个
ResNet-18专属设定上，能解释约58%的差距，其余42%未知）。这个"谁更好取决于模型"的现象直接引出第3轮。

**数据来源**：`quant/README.md` 坑#13；`quant/RESULTS.md` Section B（含逐模型5-seed数据）。

## 第3轮：energy和saliency方向不一样，混合能更好吗？

**问题**：energy和saliency在不同模型上互有胜负，没有一个统一占优的选择。

**假设**：存在某个`w_e·energy + w_s·saliency`混合点，能同时优于两个纯准则单独使用。

**验证**：ResNet-18/32/ViT，多个混合比例点（0.2/0.4/0.6/0.8等），单seed起步，ResNet-32补了3-seed。

**结论/转折**：**没有找到稳定优于两个端点的混合方案**——三个模型的混合结果基本都是在两个纯准则端点
之间插值，没有观察到协同增益。但ResNet-18上那条混合曲线呈现出**近乎单调**的形状（w_e越大越好，一路
涨到纯energy），这个形状本身很反常——如果energy和saliency是两个互不相关的独立信号，不应该表现出
这种线性走向，这个直觉促成了第4轮的理论化。

**数据来源**：`quant/RESULTS.md` Section B.5。

## 第4轮：为什么会有这种近似线性的关系？——拆解成更底层的a和g

**问题**：第3轮那条近乎单调的混合曲线暗示energy和saliency可能不是两个独立的信号，而是同一个底层量
的两种投影/加权方式。

**假设**：energy(`Σa²`)和saliency(`Σ|a|·|g|`)其实是同一个通式`Σ|a|^p·|g|^q`在两个特定点上的取值
——energy是`(p=2,q=0)`（纯幅度），saliency是`(p=1,q=1)`。如果这个通式站得住，(p,q)平面上应该还有
其他有理论意义的点，比如`(p=0,q=2)`纯梯度平方（对应经典二阶剪枝/HAWQ用的经验Fisher信息，记为
`fisher`）、`(p=2,q=2)`即`saliency²`（对二阶Taylor展开`ΔL≈g·Δa+½H·Δa²`代入`H≈g²`经验近似自然得到，
记为`fisher_a2`）。

**验证**：四个模型全测`(p,q)`网格上的四个点（energy/saliency/fisher/fisher_a2），并且额外算了四个
准则两两之间、以及贪心真实排序跟这四个准则之间的逐层Spearman相关系数。

**结论/转折**：**发现了确实更优的排序方案**——四个模型的最优点落在(p,q)平面的四个不同区域，没有
一个方向能同时解释所有模型（ResNet-18纯幅度最优、ResNet-32纯梯度最优且方向与ResNet-18完全相反、
MobileNetV2在(2,2)"全都要"角最优、ViT在(1,1)平衡点最优）；ResNet-32上`fisher`（89.34%，3-seed）
追平了贪心（89.19%），成本却只要一次前向+反向。**更关键的独立发现**：贪心的真实排序跟四个便宜准则
的Spearman相关系数全部约等于0（-0.001到+0.006），但最终精度差距只有~3pp——这直接证明贪心是对不可
解组合优化问题的一个myopic近似，不是ground truth，"贪心选的通道更精细但方向大体一致"这个弱说法
也不成立。把"saliency有时赢有时输"这个二元问题，重新表述成了"排序准则在幅度-梯度二维空间里的最优
配比是架构特异的"这个更有理论分量的问题。

**数据来源**：`quant/RESULTS.md` Section C。

## 承上启下：EXTENSION_WORK.md记录的探索，起源于"解释a^p·g^q为什么有效"

第4轮找到了`(p,q)`网格上更优的点，但**没有解释"为什么"**——`saliency=Σ|a|·|g|`里的`|a|`只是
`Δa`（量化扰动本身）的一个粗糙近似（一阶Taylor展开`Δa∝a`），不是真正测量出来的量化扰动。用户提出：
如果把这个近似换成eDQA自己机制下`Δa`的精确测量，会不会比调`(p,q)`配比更有效？—— 这个问题把"排序
准则的最优配比是什么"进一步拆解成了"量化扰动`Δa`本身该怎么精确定义"，就是`EXTENSION_WORK.md`从
第0节开始记录的那条线。这条线本身又经历了多轮"问题→假设→验证"，按更粗的粒度（phase）概括如下
（详细过程和数据见`EXTENSION_WORK.md`对应节号）：

### Phase A（EXTENSION_WORK.md §0-3）：直接把"重要性"和"量化损失"数值挂钩——三次尝试全部失败
单层诊断、纯数值失真、把相对失真度直接当全网络排序准则，三次都失败或近乎无关（rho≈0，或跑输
energy）。转折点：意识到失真度量本身没建模eDQA自己的shift-error机制（Algorithm 1/2的核心）。

### Phase B（§4-6）：引入shift-error机制后第一次成功，但确认不是新维度
`protection_gain = distortion_N − distortion_{N+m}`第一次跑赢energy，但相关性分析发现它跟energy
高度相关（0.76-0.81）——是"幅度轴"的精化版，不是独立于`(p,q)`平面的新轴；两版归一化尝试都更差。

### Phase C（§7-8）：参数敏感度 + 一次旁支
m/n_bits敏感度扫描发现排序质量本身是n,m相关的；"容量vs任务难度"理论假说被自己的推论（应该n,m无关）
部分反证；weight_norm这个零成本代理岔出一条旁支，效果不错但机制不明，悬而未决。

### Phase D（§9）：突破——pg·|g|，四模型全部验证
把pg代替saliency公式里的`|a|`、结合真实梯度，`pg·|g|`在ResNet-18/32、MobileNetV2、ViT四个模型上
**全部拿到最优或统计打平最优**。这是本条探索线里唯一一个"提出假设→验证→干净成立"的完整闭环。

### Phase E（§11）：质疑pg·|g|的普适性，进而质疑eDQA本身——问题第一次质变
测试`pg·|g|`在参考配置(n=3,m=3)之外是否站得住时，发现n=2时会被`pg²`反超，顺藤摸瓜测了1-bit退化
边界、floor vs ceiling预算重分配、2档vs3档vs均匀quantization的完整证据链——**结论越走越大：从"pg·|g|
是否普适"，变成"eDQA的mixed-precision在参考预算下有没有必要"，最后变成"均匀quantization用更少
预算就能打平/打赢整个eDQA(3,3)参考配置"**。问题从"排序方法优劣"变成了"整个协议设计是否合理"。

### Phase F（§12.1-12.6）："r不该是先验值"——问题第二次质变，从评价机制变成设计机制，最终被更简单的答案取代
提出让bit分配从数据（shift-error/|x|比例）里直接涌现，而不是用先验的固定r。验证链：诊断比例分布→
粗糙线性规则→理论水位填充(失败，撞上floor)→floor约束混合方案(打平)→单位修正→log2阶梯(一度看似
干净赢过论文参考配置)→用pg·|g|给"慷慨分配"设门槛(两模型走向相反，且18组网格证明gate这条路本身
不成立)。**这条支线最终没有产出一个能取代eDQA原有机制的新协议**——log2阶梯那次"赢"后来被证明只是
相对论文默认配置而言，换成同预算插值均匀检验后其实是输的（见Phase G）。但这条支线不是白做的：
过程中逼出了**random-ranking控制组**这个关键方法论工具（把"二档结构本身的贡献"和"排序质量的贡献"
分开测），这个工具后来直接促成了Phase G的收敛。

### Phase G（§12.7-12.9）：问题第三次质变——从"设计新机制"收缩回"诊断现有机制在哪个区间划算"，最终收敛
用户提出一个根本性纠偏：Phase E/F的大部分"eDQA不划算"结论，测试区间都选在n≥4——但n≥4的均匀方案
本身已经足够准确，根本不在eDQA要解决的问题域里，比较对象一开始就选错了。把测试范围收回论文真正
关心的n≤3，同时坚持"必须同预算对照"（不能像早期那样拿eDQA的高预算配置跟低预算均匀比），用
random-ranking控制组把"结构贡献"和"排序贡献"分开测，链条是：

1. n=3,m=1对同预算插值均匀是大幅、扎实的领先（3-seed确认：+7.56pp/+2.88pp），且排序贡献
   （真实排序−random_rank）远大于n≥4区间同样的分解——floor越低、曲线越陡，排序越值钱。
2. 用同一把尺子回头检验论文默认的(3,3)：**发现(3,3)对同预算插值均匀反而是倒输的**
   （-2.21pp/-1.55pp），且m=1→2→3这条margin曲线是单调递减的，(3,2)还是骑墙配置（一个模型输
   一个模型薄赢），只有m=1两个模型都确认赢。**论文自己的Figure 4（m边际递减）和对ResNet-18的
   解释（小模型channel普遍重要）都为这个结论埋下了伏笔，但论文没有走到"跟同预算方案比较"这一步**。
3. 顺带把n≤2（floor损坏到无法挽回，(2,4)预算推到4.2仍打不过均匀3-bit）和n≥4（均匀本身帕累托
   最优，排序+shift-error两个环节都可整体跳过）的边界也补齐，画出了一条完整的"eDQA何时划算"曲线。
4. **最终结论**：目前测过的(n≤3,m≤3)空间里，唯一确认站得住、优势扎实的组合是**(n=3,m=1)**，
   本质上是一种"排序引导的智能3.5-bit量化"——跟HAWQ-V2（已在Bibliography[12]）、FracBits等
   fractional/mixed-precision bit-width文献是同一概念谱系，但成本低得多（不需要Hessian trace
   计算或差分NAS搜索）。

这是整条延伸探索线**第一次真正收敛**的地方——不再持续分支，有一个精炼、可以直接写成dissertation
一节的结论，而且经过3-seed验证。

**由此触发的dissertation结构决策**：这轮探索的体量和性质，已经不适合塞进原来"复现+优化排序"两段式
框架里的"优化排序"部分——它回答的是完全不同的一类问题（不是"哪个排序准则最好"，是"eDQA这套机制
本身在什么条件下值得用"）。用户据此决定把dissertation整体框架改成**"复现、延伸（应用场景分析）、
优化排序"三段式**，Phase D（pg·\|g\|）对应"优化排序"，Phase E-G对应新增的"延伸"这一段，两条线
独立但互补——一条回答"选哪个准则"，一条回答"怎么配置eDQA自身的超参数"。

总计约25轮独立的"问题→假设→验证"循环，现在**全部收敛**。整条线从"贪心太慢"一路走到"eDQA真正
划算的区间只有(n=3,m=1)一个点、本质是排序引导的智能3.5-bit量化"，构成一条连贯、每一步都有明确

叙事。这条主线加上Phase D的pg·\|g\|发现，足够支撑dissertation新框架里"延伸：应用场景分析"和
"优化排序"两个独立章节；Phase F本身虽然没有直接产出结论，但作为"过程"（尤其是random-ranking
控制组工具的来源）值得在延伸章节里简要提及，不需要展开成独立小节。
